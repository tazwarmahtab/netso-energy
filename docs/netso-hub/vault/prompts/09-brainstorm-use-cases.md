# Prompt 09: Brainstorm Use Cases

**Purpose:** Discover the 5 highest-value knowledge compilation use cases for your specific industry. Most teams don't realize what value is locked in scattered documents. This prompt surfaces industry-specific opportunities, not generic ones.

**When to use:** After your wiki has 15+ pages. Also useful when a new team asks "can the wiki help us with X?" and you want to evaluate whether it can.

---

## Thinking Logic (for AI assistants running this prompt)

Before brainstorming use cases, silently work through these checks:

1. **INDUSTRY DETECTION:** What industry is the user in? This determines which KPIs to use, what source types are most common, and what "high-value" means. Don't default to SaaS metrics for every user.

2. **COMPANY STAGE:** A pre-revenue startup and a $50M company have different use case priorities. Pre-revenue: strategic positioning, investor prep, competitive intelligence. Scaling: deal efficiency, team onboarding, process documentation. Enterprise: cross-department knowledge sharing, institutional memory, compliance.

3. **TEAM SIZE REALISM:** Don't recommend use cases that require dedicated maintenance staff if the team has 5 people. Every use case recommendation should include a realistic effort estimate.

4. **EXISTING WIKI STATE:** If the user mentions their wiki already has pages, calibrate use cases to what's buildable from the existing foundation. Don't recommend starting from scratch on a domain that overlaps with existing content.

5. **REVENUE CONNECTION:** Every use case should trace to a business outcome. If you can't articulate how a use case improves a KPI from the metrics list above, it's not a high-value use case. Drop it and find one that connects.

---

## The Prompt

```
I work in [INDUSTRY: SaaS / fintech / healthcare / e-commerce / consulting / media / education / manufacturing / etc.] at a company with [SIZE] employees.

Before brainstorming, identify the primary revenue and success metrics for my industry and stage. Express all estimates using metrics that actually apply to my business:

- Community-led / developer tools: docs traffic, GitHub stars/forks, Discord/Slack community growth, contributor count, developer adoption rate
- B2B SaaS: ARR, win rate, pipeline velocity, CAC payback, net revenue retention
- Media / publishing / events: CPM, sponsor renewal rate, subscriber growth, event ticket revenue, audience engagement
- Consulting / professional services: utilization rate, project margin, repeat engagement rate, proposal win rate, time-to-staff
- Consumer / DTC / e-commerce: CAC, LTV, repeat purchase rate, category share, review sentiment
- Manufacturing / logistics: supplier lead time accuracy, defect rate, order fulfillment speed, cost per unit
- Healthcare / pharma: clinical trial enrollment rate, regulatory approval timeline, formulary placement, evidence quality score
- If my industry doesn't match any of these, ask me what our 2-3 most important business metrics are before proceeding.

Use these metrics (not generic "pipeline velocity" for every industry) when estimating revenue impact for each use case.

What are the 5 highest-value knowledge compilation use cases for my specific industry? For each one:
- What raw sources would feed it?
- What would the compiled wiki surface that scattered documents can't?
- What's the estimated time saved per week for a team of [SIZE]?
- What's the revenue impact (direct pipeline, retention, speed-to-close, etc.)?

Don't give me generic answers. Make each one specific to how [INDUSTRY] companies actually operate.
```

---

## What You'll Get

5 industry-specific wiki use cases with source requirements, time savings estimates, and revenue impact per use case. Each one is tailored to your actual business model, not a generic template.

**Next step:** Pick the top 2-3 use cases and work backward. What pages do you need to build to support them? What sources feed those pages? Build in that order.

**Pro tip:** Be specific about your industry and company size for better results. Mention your company stage for more calibrated estimates.
